# 《白山茶遗嘱》V0.4 Gameplay Design

> 状态：开发前设计冻结稿
> 目标平台：React + TypeScript + Vite 网页游戏／PWA
> 约束：本文件只定义表现与交互，不修改现有第一章剧情逻辑。

## 0. 体验原则

1. 答案不得由 NPC 直接说出。NPC 只能提供立场、记忆、谎言和可验证事实。
2. 真相必须经过三类玩家操作：
   - 证据组合：判断什么可以互相证明；
   - 时间线分析：判断物质、人物和行为的先后；
   - 人物关系推理：判断谁有权、能力和心理需要替谁作决定。
3. 演出服务于信息层级，不遮挡证据，也不替代推理。
4. 所有新系统保持 JSON 驱动，React 只负责解释内容、条件和状态。
5. 手机竖屏与桌面端共享信息结构；桌面端并排展示，移动端改为分层抽屉和全屏详情。

# 1. 过场动画系统

## 1.1 实现边界

采用 React 状态切换、CSS `opacity/transform/filter`、少量 SVG 描边动画和 Web Audio／HTML Audio。单段镜头 0.25—1.2 秒，章节演出最长不超过 20 秒。不开 3D 场景、不做实时角色骨骼、不依赖大型视频素材。

建议每段演出由 JSON 描述：

- `id`：演出 ID
- `trigger`：触发事件或条件
- `blocking`：是否暂停操作
- `shots`：镜头列表
- `type`：`caption`、`image`、`panel`、`evidence`、`connection`、`fade`
- `durationMs`
- `text`／`assetId`
- `audioCue`
- `transition`
- `skippable`
- `reducedMotionFallback`

动画播放只写入“已观看演出 ID”，不得直接改写案件结论。剧情状态仍由事件系统推进。

## 1.2 黑屏字幕

### 用途

- 序章时间地点；
- 章节开场的调查命题；
- 章节末的认知修正；
- 最终选择前的停顿。

### 表现

- 背景由深黑渐入黑绿；
- 文本按句而非逐字出现，避免中文打字机效果拖慢阅读；
- 重要时间使用冷白，概念词如“安全”“同意”“她”使用暗金；
- 点击或触摸可立即显示完整句，再次点击进入下一镜头。

### 可访问性

- 字幕始终可见，不依赖音频传达关键信息；
- 支持关闭闪烁、缩短淡入和一键跳过已看演出；
- 字号移动端不低于 18px，行高不低于 1.6。

## 1.3 风雪声音

### 声音层级

1. **环境底层**：远风、窗缝、偶发树枝敲窗；
2. **空间层**：茶室瓷器、走廊木地板、书房纸张；
3. **事件层**：喷雾短响、证据落桌、金线绷紧、章节落幕；
4. **静默层**：重要伦理台词前主动降低环境音。

### 交互规则

- 场景切换时交叉淡化，避免音轨硬切；
- 浏览长文档时降低环境音 20%；
- 应用进入后台时暂停，恢复后不重播事件音效；
- 设置中独立控制环境音、演出音、语音预留和总音量。

## 1.4 场景转场

| 场景变化 | 动画 | 时长 | 信息目的 |
|---|---|---:|---|
| 静园区域切换 | 当前面板轻微后退并虚化，新面板从风雪遮罩后进入 | 450—650ms | 建立空间距离 |
| 调查／对话切换 | 侧向推入，对话人物卡固定在视线中心 | 300—450ms | 表示调查模式变化 |
| 过去／现在切换 | 色彩短暂褪为冷灰，时间戳压入 | 500ms | 防止回忆与当下混淆 |
| 证据详情进入 | 卡片从原位置放大为详情层 | 250—350ms | 保持来源连续性 |
| 章节切换 | 黑屏、章节名、白山茶花瓣剪影 | 1.5—3s | 给玩家认知重置时间 |

移动端不做大幅横移，优先使用淡入和小距离纵向位移，减少晕动。

## 1.5 证据发现动画

### 普通材料

- 卡片边缘出现一次低亮冷白描边；
- 右下角显示来源位置；
- 收入材料库时缩小并飞向底部“案件”入口，但移动距离不超过屏幕 30%。

### Observation

- 玩家查看特定细节后，局部高亮；
- 一行观察文本从图像／文档旁滑出；
- 只提示“发现观察”，不提示它是否关键。

### 正式证据

- 两个或更多材料满足条件时，暗金细线在它们之间绘制；
- 线条汇聚为正式证据卡；
- 触觉设备可使用一次轻微振动；
- 证据重要度不以夸张特效泄露，核心与普通证据使用同一基础动画。

### 重复查看

已发现证据不再播放完整动画，只显示短促的来源关联反馈。

## 1.6 推理连接与提交动画

### 连接

- 证据拖入槽位后，金线从卡片锚点延伸到命题；
- 不兼容证据显示松弛灰线，不立即判错；
- 满足结构要求时，金线绷紧，但不预告结论正确。

### 提交

1. 背景环境音降低；
2. 证据卡按玩家排列顺序依次亮起；
3. 连接线经过“事实—因果—人物”三个检查节点；
4. 正确时线保持暗金，错误时在具体断点断开；
5. 反馈只说明哪一类因果未被证明，不直接给出缺失证据名称。

### 错误反馈示例

- “你证明了她碰过杯子，但没有证明她加入了致死物。”
- “体内剂量成立，进入身体的路径仍未成立。”
- “三个人共享一个秘密，不等于他们共享同一个行动。”

## 1.7 章节结束动画

每章结尾固定包含：

1. 当章“已确认事实”三至五条；
2. 被否定的旧推测一至两条；
3. 新增未解决疑点一至三个；
4. 一段不超过 15 秒的情绪演出；
5. 自动存档反馈；
6. 下一章标题，但不泄露下一反转。

章节结尾允许回到自由调查，不强制玩家立即进入下一章。

# 2. 调查体验升级

## 2.1 统一案件数据层

五个调查工具共享同一批实体 ID，避免复制事实：

- `characterId`
- `materialId`
- `observationId`
- `evidenceId`
- `timelineEventId`
- `reasoningId`
- `relationshipId`
- `noteId`

所有关联只引用 ID。章节 JSON 决定首次可见性、解锁条件、错误解释、重新解释文本和演出触发。UI 不硬编码人物、证据或章节答案。

## 2.2 人物关系图

### 玩家用途

- 查看明面身份与已确认关系；
- 标记保护对象、冲突对象和信息控制关系；
- 对比同一人物在不同章节的关系变化。

### 节点

- 头像／剪影、姓名、表面身份；
- 当前情绪状态；
- 已确认事实数量；
- “仍有矛盾”标记，但不显示“凶手嫌疑值”。

### 边

边不是单一“亲属关系”，而是可叠加的关系层：

- `family`：亲属或表面亲属；
- `protects`：保护；
- `controls`：控制；
- `withholdsFrom`：隐瞒；
- `conflictsWith`：冲突；
- `trustedBy`：信任。

边随证据解锁重新命名。例如：

`沈慈云 → 沈意舒：监护`
第二章后变为：`救援者／身份控制者`
第五章后变为：`曾获同意的救援者／拒绝更新同意的控制者`

身份谜题相关关系必须区分生物学关系与社会身份：

- `沈慈云 → 沈小鹿／沈意舒`：生物学上的亲姨母；新身份资料中的法定母亲；
- `沈仪真 → 沈小鹿／沈意舒`：生物学上的亲表姐；共同生活十二年的社会身份姐姐；
- 第二章不能因两人都姓“沈”自动确认身份同一，关系重释必须由双重登记、栖湖旧照片与封存目录共同触发。

### 交互

- 点击边查看支持它的证据；
- 玩家可提出临时关系假设，但临时边使用虚线；
- 系统只在完成推理后把虚线转为确认边；
- 移动端按人物为中心展开一层关系，避免整图缩得不可读。

## 2.3 时间线

### 三层时间尺度

1. **十二年前**：旧案、身份、承诺；
2. **案发前阶段**：三周、四天、当天准备；
3. **案发分钟级**：16:40—23:00。

### 信息状态

每个时间事件具有：

- `claimed`：某人声称；
- `corroborated`：有独立材料支持；
- `inferred`：由玩家推断；
- `contradicted`：存在矛盾；
- `confirmed`：推理节点确认。

### 玩家操作

- 将事件拖入时间槽；
- 把材料绑定到事件；
- 比较“谁说的时间”和“设备记录时间”；
- 切换人物轨道，观察机会窗口；
- 在第四章完成“饮茶—用喷雾—再次饮茶—倒地”排序；
- 在第五章完成“非致命方案失败—替换喷雾—取回凶器”排序。

系统不自动替玩家排好完整时间线。可提供相邻顺序错误反馈，但不显示正确位置。

## 2.4 侦探墙

### 定位

侦探墙是自由假设空间，不等同于正式推理提交。玩家可以犯错、保存多个版本、给连线写标签。

### 节点类型

- 人物
- 材料
- 观察
- 正式证据
- 时间事件
- 玩家笔记
- 待证明命题

### 连线类型

- 支持
- 反驳
- 来源
- 发生在
- 接触过
- 保护
- 控制
- 玩家自定义

### 关键设计

- 初始提供“毒茶”假设板，引导玩家形成合理错误方向；
- 第一章结尾允许保存错误板，不强制删除；
- 第四章可把原板复制为“喷雾路径”版本，让玩家直观看见同一证据如何被重释；
- 最终结算展示玩家第一版与最终版的差异，而不是只展示正确答案。

## 2.5 证据连线

正式证据的生成结构：

`原始材料 → Observation → Evidence → Reasoning`

示例：

`杯沿照片 E02`
→ `观察：唇痕存在两次叠加方向`
＋ `口腔喷雾辅料 E21`
→ `证据：喷雾后再次饮茶 E23`
＋ `体内／杯中浓度 E20`
→ `推理：杯中乌头为反向污染`

### 规则

- 每个正式证据必须能回溯到原始材料；
- 每个推理必须显示使用了哪些证据、排除了哪些解释；
- 证据可以支持多个推理，不能因用过一次而消耗；
- NPC 出示证据只改变对话分支，不自动确认玩家的解释；
- 关键证据至少有一次错误解释和一次重新解释。

## 2.6 案件笔记

### 自动部分

- **已确认事实**：只记录完成推理节点后的事实；
- **当前推测**：根据玩家保存的侦探墙命题生成；
- **未解决疑点**：由章节 JSON 按条件更新；
- **人物说法**：逐条保留原话和出现场景；
- **被推翻推理**：保存错误提交及具体断点。

### 玩家部分

- 自由文本；
- 给证据加短标签；
- 收藏关键台词；
- 在人物、时间事件、材料之间插入个人引用。

### 防剧透原则

自动笔记只复述玩家已确认的信息，不出现“你应该调查”“真正凶器”等引导性结论。

# 3. NPC 对话与情绪变化

## 3.1 固定情绪状态

不使用 AI NPC。每个人物由 JSON 定义有限状态：

- `neutral`：礼貌／克制
- `guarded`：回避／反问
- `angry`：对抗
- `fractured`：叙述出现矛盾或情绪失守
- `resolved`：接受后果或明确选择

状态由章节、已发现证据、曾出示证据和玩家对话选择共同决定。

## 3.2 视觉反馈

- 头像不做复杂口型；使用两到四张情绪立绘或同一图像的裁切、明暗、视线变化；
- 情绪改变时采用 200—350ms 的颜色、对比度和位置变化；
- 谎言不使用红光、心跳或“撒谎”标签，避免 UI 泄露答案；
- 玩家持续代替沈意舒作答时，她的状态从 `guarded` 转为 `withdrawn`，但不立即解释原因。

## 3.3 证据出示

出示证据可能产生：

- 新陈述；
- 对旧陈述的修订；
- 拒绝回应；
- 解锁另一个人物的话题；
- 改变关系边；
- 增加“替她决定”或“尊重选择”隐性计数。

同一证据对不同人物必须有不同作用。不能用“正确证据”作为万能钥匙。

# 4. UI 视觉规范建议

## 4.1 色彩

沿用当前黑绿、冷色、白山茶、金色证据线：

| 用途 | 建议色感 | 规则 |
|---|---|---|
| 主背景 | 近黑的深绿 | 避免纯黑吞掉照片细节 |
| 面板 | 冷灰绿／半透明墨绿 | 信息层次靠明度，不靠大量边框 |
| 正文 | 微冷白 | 长文对比度满足可读性 |
| 次要文本 | 灰蓝 | 不用于关键证据正文 |
| 证据连接 | 低饱和暗金 | 只用于已建立的关系与焦点 |
| 未确认连接 | 冷灰 | 与暗金明显区分 |
| 危险／矛盾 | 暗红褐 | 少量使用，不等同于凶手标记 |
| 白山茶 | 乳白、冷影 | 作为章节停顿与记忆意象 |

## 4.2 字体与排版

- 标题使用有文学感但高可读的中文衬线字体回退栈；
- 正文使用系统无衬线字体；
- 桌面正文 16—18px，移动端 17—19px；
- 证据元信息不低于 14px；
- 长文档行宽控制在约 34—42 个汉字；
- 可点击正文链接、证据引用和按钮不得只靠颜色区分。

## 4.3 页面转场

- 常规面板：250—450ms；
- 章节标题：1.5—3s；
- 禁止所有页面同时使用缩放、模糊、位移；
- 用户快速连续导航时取消前一动画，保证界面响应；
- `prefers-reduced-motion` 下改为 100ms 淡入或无动画。

## 4.4 证据发现反馈

- 视觉：边缘暗金、来源文字、短线连接；
- 声音：轻微纸张／金属线音；
- 触觉：支持时单次轻振；
- 文本：明确区分“获得材料”“形成观察”“确认为证据”；
- 禁止使用稀有度、星级或金色爆光暗示剧情重要性。

## 4.5 章节标题动画

统一模板：

1. 风雪遮罩；
2. 章序号小字出现；
3. 章节名分两行或单行淡入；
4. 一朵白山茶由清晰变为轻微失焦；
5. 当前调查命题出现；
6. 进入场景。

各章只替换音色、背景局部和命题，不单独制作高成本动画。

## 4.6 手机竖屏

- 底部固定四个主入口：调查、案件、对话、目标；
- 最小触控区域 44×44px，主要按钮建议 48px 高；
- 人物关系图以焦点人物为中心分页展开；
- 时间线默认显示单轨，横向滑动切换人物；
- 侦探墙支持双指缩放，但同时提供“节点列表”无手势模式；
- 图片查看支持双指缩放、双击复位和拖动；
- 长文档保留阅读进度，返回后回到原位置；
- 推理槽位采用点选添加，同时保留桌面拖拽。

# 5. JSON 驱动边界

## 5.1 内容层应配置

- 章节、地点、调查目标；
- 材料、观察、证据和来源关系；
- 人物、关系边、情绪状态与对话；
- 时间事件及其可信状态；
- 侦探墙初始模板；
- 推理槽位、接受组合、错误反馈；
- 演出镜头、音效提示、章节结尾；
- 结局条件与文本。

## 5.2 引擎层应通用处理

- 条件判断；
- 事件执行；
- 状态持久化；
- 动画队列；
- 图节点布局与连线交互；
- 时间线排序验证；
- 推理提交；
- 触控／键盘／无动画适配；
- 存档迁移。

## 5.3 不应写入 UI 组件

- 人物姓名；
- 证据名称；
- “沈仪真是真凶”等答案；
- 固定章节数；
- 具体结局阈值；
- 对话解锁条件；
- 特定证据组合。

# 6. 五章系统开放节奏

| 阶段 | 新开放能力 | 设计目的 |
|---|---|---|
| 序章 | 调查目标、基础材料查看 | 降低开场认知负担 |
| 第一章 | 材料—观察—证据、对话、第一次推理 | 完成现有核心闭环 |
| 第二章 | 人物关系图、跨年代材料 | 区分“沈家两个女孩”“身份冒用”与“同一人的两个身份阶段”，处理身份与救援关系 |
| 第三章 | 多人物轨道、案件笔记升级 | 分离各自保护动机 |
| 第四章 | 分钟级时间线、侦探墙复制、复杂证据连线 | 玩家自主重建死亡机制 |
| 第五章 | 完整关系重释、公开范围选择、结局判定 | 把自主性纳入最终交互 |

系统开放后可回看前章内容。关系图和时间线不替旧证据新增事实，只提供新的组织方式。

# 7. 验收标准

## 演出

- 所有关键信息在关闭声音、减少动态模式下仍完整可得；
- 已看演出可跳过，首次关键演出不可因误触永久错过；
- 低端手机动画不阻断调查操作；
- 章节结束演出能够回顾事实但不泄露下一章答案。

## 调查工具

- 任一正式证据可追溯至原始材料；
- 关系边、时间事件和笔记均由 ID 引用同一内容实体；
- 玩家可以保存错误假设，不被系统自动纠正；
- 第四章必须能仅靠时间排序和证据组合推出喷雾路径；
- 第五章必须能仅靠已出现证据锁定沈仪真，不依赖最终录音。

## 主题交互

- 至少六个节点允许玩家选择“询问她”或“替她决定”；
- 隐藏坏结局由累计行为触发，不由最后一个按钮突然判定；
- 最佳结局不要求玩家替沈意舒选择名字或公开全部信息；
- 最佳结局必须允许沈意舒自行决定继续使用“沈意舒”、恢复“沈小鹿”或选择新的名字，界面不展示任何选项为系统推荐；
- 结算同时呈现调查完成度与“是否尊重当事人选择”，两者互不替代。
